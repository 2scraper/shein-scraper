# Contributing

1. Fork, branch, make your change.
2. `pip install -r requirements-playwright.txt` (or `-selenium` / `-puppeteer`) and run `python3 smoke_test.py` — it must pass with **no** engine installed at all, so if you're only testing one engine, that's still a meaningful run.
3. **If you touched `shein_parser.py`: read its module docstring first.** Unlike most of this family's first builds, `window.gbRawData` (the search/category listing path) and the product-detail `ProductGroup` JSON-LD are both grounded in a real, live browser capture — not a guess. The DOM fallback selectors and `--sort`'s real query-parameter shape are the parts still marked `# TODO: verify live` / unconfirmed. If you have a real, scrubbed `--dump-html` capture that confirms or corrects any of this (especially whether scrolling actually grows `gbRawData` past its first batch — see README "Pagination"), save it under `tests/fixtures/`, update `shein_parser.py` to match, and remove the relevant `# TODO`/unconfirmed note. Don't remove one without a capture backing it up.
4. Keep the three engines behaving identically: same exit codes, same `Product` schema, same CLI flags, same `_resolve_start_url()` routing between a listing URL and a product-detail URL. If one needs to diverge (see `selenium_scraper.py`'s CDP-credential limitation for an example), say why in a comment.
5. Open a PR. CI runs the offline suite on two Python versions plus one `engine-smoke` job per engine, each in its own virtualenv, plus a daily `canary` job that runs the local-first default against the real site with no secrets (see `TESTING.md`).

Bug reports and feature requests: open an issue. Please include the exact command you ran and the `.meta.json` sidecar from the run (or note that none was written — that's itself informative, see `output_writer.finish_run`'s docstring), not just a description. If you're reporting that zero products came back, attaching a `--dump-html` capture is the single most useful thing you can add. If you hit the `/risk/challenge` gateway (see README "Known limitations"), noting whether it recurred on a retry (and with what proxy/fingerprint settings, if any) helps confirm whether it's really a per-context risk score rather than a blanket rule.
